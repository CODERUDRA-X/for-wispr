# Page notes — presentation guide

## Home
The hero treats voice as the portfolio's central input method: the particle field reacts to pointer movement and recognized speech events, and the browser demo is immediately testable. The numbers strip is intentionally followed by context, including the two-person Ideathon miss.

## The Thread
The five chapters use a repeatable Did / Went wrong / Learned / Did next structure. It is a build log rather than a résumé timeline. The desktop rail tracks progress; on mobile each chapter becomes an accordion so the reading order remains clear.

## Builds
Each project receives a custom interaction derived from its actual purpose: a four-agent consensus explainer, a procedural power-line inspection scene with a detection reveal, and a deterministic Hinglish-to-time parser. The first two visuals explicitly distinguish explanation from real model inference.

## Community
A 600-dot field and a two-dot field share the same canvas size. The attendance contrast is impossible to miss; the page then asks for the distribution story and the post-failure changes instead of inventing them.

## Campaigns
Three flip cards show goal, channel, proposed metric, and first seven days. Every card is labelled as a proposal. Tilt and spotlight are quiet supporting effects; the plan remains readable without them.

## Voice receipts
The scrubber is ready, but the source excerpts are deliberately unfilled. A fake “raw” voice note would undermine the point of the page, so the missing source and edit remain visible as fill chips.

## Ask me
Six preset questions reveal local, prewritten answers. Missing role ownership, product-fit details, and logistics are flagged instead of answered with invented claims.

## Contact
The page puts the supplied education and base details first, then makes start-date and Bangalore logistics explicit fill-ins. The primary contact action uses the verified LinkedIn profile; no email address is guessed.
